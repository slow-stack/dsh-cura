# v0.9.2 — 大脑代理不再自开端口，改走宿主 webServer

## 修了什么

语音通话的「大脑代理」原先自己 `http.createServer` 监听 `127.0.0.1:8765`，只靠「绑回环地址」防护：本机任意网页都能直接 POST 打进来白嫖模型额度。现在改为向宿主 webServer 注册 `/cura/v1/chat/completions`，每个请求先过准入判决。

- **跨站一律 403**，本机 Python 引擎改用插件进程内现生成、不落盘的 bearer token。
- 其余请求交给宿主的 `connection.requestRejection` 判：Host/Origin 栅栏 + 会话凭据。
- **服务缺失或判决抛错时 fail closed 返回 503**，不放行。
- 准入在调模型之前完成，被拒的请求完全不碰 llm。

## 升级后要注意

- `port` 配置项**已废弃**（默认值改 0），填任何值都不会再监听。想确认代理地址，看面板「语音通话」页里显示的 `http://<宿主地址>:<端口>/cura/v1`。
- 单独跑 `engine/engine.py` 时不要再指向 `/cura/v1`：那条路由要插件进程内的 token，会 401。插件托管启动时会自动用环境变量把地址与 token 交给引擎。
- 引擎启动改为等宿主 webServer 绑定端口后再拉（最多等 20 秒），等不到会明确记一条日志，不再拉起一个连不上大脑的哑巴进程。

## 验证

- 真机实测（重启后的 DSH）：`8765` 已无监听；`POST /cura/v1/chat/completions` 无凭据 → **401**、带 `sec-fetch-site: cross-site` → **403**。
- 新增 `tests/test-brain.mjs` 六组，其中一组真起 server 打请求：无凭据 503/401 且 chat 调用次数为 0、跨站带对 token 仍 403、GET 405、坏 JSON 400、超体积 413、上游 503 透传。
- 全套 9 套测试通过，Node 20 / 22 双档；8 个变异全部被测试抓住（跨站检查失效、服务缺失 fail open、先调模型再判准入、任意 token 都算对、超大体不拦、错误一律 502、引擎不等地址就启动等）。
